# Save-manager determinism fixture

- `save-determinism-v1.json` pins the two data-hash-safe determinism surfaces of the save manager as fixture evidence, in the same style as the M5/M10/M11 fixtures.
- **Bundle-merge rule** (`bundleMerge`): a seeded storage plus a fixed import bundle exercise every merge outcome — newer snapshot merges in place (existing key/name kept, snapshot adopted), equal-or-older is kept out (`keptLocal`), fresh campaigns import, a second same-campaign entry later in the bundle merges into the first (sequential simulation), and non-object / foreign-key entries are skipped. The plan preview and the applied import are pinned to agree exactly.
- **Autosave ring** (`autosaveRing`): five writes under a retention cap (with a same-timestamp collision that pins the `-2` key suffix), one prune, a targeted delete, and a promotion to a named save — pinning the ring's keys, ordering, `campaignHash` values, and the derived promotion name. A **retention-cap leg** (`capPruneSteps` 3 → 2 → 1) then lowers the cap after the ring is populated, exercising `pruneAutosaves` directly exactly as the dashboard's "Keep last N snapshots" slider does on cap change: a no-op at the current cap, then two deterministic prunes leaving only the newest snapshot — so the immediate-prune path is pinned as data-hash-safe evidence alongside write-time trimming.
>- **Remote sync** (`remoteSync`): a scripted four-step arc run against the live `RemoteBundleStorage` backend over an in-memory endpoint that mirrors the mock server's wire contract exactly (GET 404 when empty, compare-and-set PUT with string revisions, `putForce` for a concurrent writer). The arc is push → concurrent writer advances the server → local edit makes the next sync a conflict touching neither side → force pull adopts the remote bundle — pinning each step's status, **the backend's `SyncResult.message`** (the exact status-line text the panel surfaces), server revision, and local/remote `fnv1a32` content fingerprints, plus the **persisted `SyncMeta` baseline** (`lastSyncedFingerprint` and `lastRemoteRevision` — the deterministic fields of the "Last synced … - server revision …" line; the live `syncedAt` timestamp is excluded exactly like `generatedAt`/`exportedAt`) and the server's final named-save set.
- Every pinned value carries a canonical hash: per-scenario `observationHash` (`c14n-fnv1a64-v1`) over the deterministic projection (timestamps, ids, and timestamps are fixed inputs, so nothing volatile is hashed) and a whole-fixture `fixtureHash`.

Regenerate with `npm run fixtures:saves` and verify against the live save-manager code with `npm run fixtures:verify` (which now includes `verify-save-determinism.ts`). The fixture re-derives all three scenarios from its own pinned inputs, so a change to the merge rule, the ring retention, the remote-sync revision/fingerprint logic, campaign hashing, or payload serialization fails the gate with the pinned-vs-actual hash in the error.
