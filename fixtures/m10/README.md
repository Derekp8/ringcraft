# M10 golden AI decision log

- `ai-decision-log-v1.json` is the golden decision log for the M10 default-identity gate: every decision the v1 deterministic policy makes across the engine's twelve decision-state kinds, captured from seeded headless matches (plus one scripted-dice run that forces the knockout-pin state, and one seeded (1991) `ruthless` run — `ruthless-singles-1991` — so the non-default 2-ply policy's replay contract is covered by the same gate).
- Each run also records the canonical `finalStateHash` of its terminal match state, and every decision carries a `hash` column (`fnv1a32` over seed/tick/actorId/kind/chosenKey) so a single changed decision is located by kind, tick, and seed. `npm run fixtures:verify` asserts the replay reproduces the decision sequence, the per-decision hash column, and the terminal hash — the corpus pins the whole post-match state, not just the choices. The selector is difficulty-aware: it routes from each run's own `config.aiDifficulty` (`choosePolicyAction` with the config value, which for standard is the deterministic v1 path), so the ruthless run replays under the 2-ply policy while every other run stays on the default identity.

Regenerate with `npm run fixtures:m10` and verify that today's policy replays the log byte-identically with `npm run fixtures:verify`. The corpus fixture's content hash is pinned in `tests/m10-ai-corpus.test.ts`; a regeneration that changes any decision, final state hash (or roster, or seed) must be reviewed and re-pinned deliberately.

### Line endings and the content hash (autocrlf hazard)

The fixture's content hash is computed from the file's **text**, so it must be stable regardless of how the checkout materializes line endings. The canonical clean-room gate runs on Linux (LF checkouts), but a Windows checkout with `core.autocrlf=true` writes the fixture as CRLF — and because the hash feeds off the raw text (`?raw` in the test, `readFile` in the verifiers), a bare `fnv1a32(raw)` would shift on every EOL flavor. Every hashing site therefore normalizes line endings first via `normalizeFixtureEol` (`scripts/m10-ai-corpus.ts`): CRLF and lone CR are folded to LF before the SHA-256/fnv1a32 is taken, so the pinned identity is identical on LF, CRLF, and mixed checkouts. Keep `normalizeFixtureEol` in front of any new place that hashes the fixture text; `JSON.parse` downstream is EOL-agnostic and unaffected.

Locate drift with `npm run fixtures:m10:diff` (`scripts/diff-m10-corpus.ts`, optionally pointed at a candidate fixture path): it replays the whole corpus and reports **every** diverged decision across all runs — seed, tick, kind, and both hash sides — plus any run-level count or final-state-hash divergences, exiting 1 when anything diverges. The fast-failing `fixtures:verify` gate and the diff tool share one locating implementation (`diffCorpusFixture` in `scripts/m10-ai-corpus.ts`), and `tests/m10-ai-corpus.test.ts` demonstrates the locating power by flipping decision hashes in a scratch copy and asserting the exact seed/tick/kind is named for every mutated decision.
