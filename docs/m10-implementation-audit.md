# M10 implementation audit — AI Difficulty Ladder and Bounded Lookahead

## Verdict

M10 delivers the four-step AI difficulty ladder and bounded multi-ply search defined by `docs/superpowers/specs/2026-08-13-m10-ai-depth-design.md`, with `standard` (and an absent field) byte-identical to the pre-M10 policy. No M0–M5 rules, campaign schema, data pack, hash module, PRNG stream, fixture, or replay format changed.

## Implemented surfaces

| Area | Evidence |
|---|---|
| Policy table | `AI_POLICY_VERSION = "asw91-ai-policy-v1"` and `AI_DIFFICULTIES = ["novice", "standard", "veteran", "ruthless"]` in `src/core/ai.ts`; policy configuration only — not part of `M5_DATA_HASH` or the match `dataHash` |
| Default identity | `chooseDeterministicPolicyAction` remains the `standard` code path; `choosePolicyAction`/`chooseAiAction` dispatch to it for `standard`/`undefined` and consume zero PRNG values |
| Novice | v1 greedy scoring plus hash-derived mistake injection (`fnv1a32` of seed/tick/actor/kind/difficulty — never the dice stream), playing the k-th best legal action with probability 0.35 (`NOVICE_MISTAKE_RATE`, pinned by the novice-end sweep; the weak-end separation gate asserts `novice < standard − 0.02` per seed window and `− 0.10` aggregate) |
| Veteran | 1-ply lookahead: each candidate action applied to a discarded clone, then scored as `v1 + 0.15 × eval delta` against a pure positional `evaluateState` |
| Ruthless | 2-ply: advances the clone to the opponent's decision and applies the opponent's greedy-by-evaluation response (top 6 candidates, node-budget bounded) before the final evaluation, weighted 0.15 |
| Search budget | `AI_SEARCH_CLONE_BUDGET = 40` discarded clones per top-level decision; candidates past the budget keep their v1 score; any search failure falls back to v1 and never throws into a live match |
| Search hygiene | `resolveDecisionOnce` clones the dynamic state (shared static roster/maneuvers, copied RNG) via `cloneMatchStateForSearch`; search-scoped clones are marked in a `WeakSet` so their discarded events skip the per-event full-state hash; marked states advance in place without a JSON round-trip |
| Evaluation | `evaluateState` is a pure function of visible state: pending pin/submission win chance, damage/endurance pool ratios, opponent counter-threat, Hold control, referee alertness, and tag position — no RNG |
| Campaign integration | `CampaignConfig.aiDifficulty` → `CampaignState.aiDifficulty` → copied onto each `ScheduledMatch` at schedule time → into `MatchConfiguration` via `beginScheduledMatch`/`createMatch` → into `hashMatchState` and stored `replayConfig` |
| Validation | `createMatch` rejects unknown difficulties; `validateCampaignState` reports unsupported campaign/schedule values; the optional fields pass the invariant checker unchanged and round-trip through `asw91-campaign-v1` |
| UI | Exhibition "AI difficulty" select (default `standard`); Career setup select applied to the campaign default; dashboard opposition-difficulty label; onboarding copy stating difficulty is visible and never changes rules dice; a `DifficultyHint` panel under both setup selects (`AI_DIFFICULTY_HINTS` in `src/core/ai.ts`, wired via `aria-describedby`) explaining what each level changes, with the active level highlighted |

## Verification

- **Default identity:** the golden `fixtures/m10/ai-decision-log-v1.json` corpus (1,050 decisions, all 12 decision-state kinds, pinned by `fnv1a32` → `64e1f4af`) replays byte-identically through the v1 chooser **and** through `choosePolicyAction` with both `undefined` and `"standard"`. Every decision carries a per-decision `hash` column (`fnv1a32` over seed/tick/actorId/kind/chosenKey) so a single changed decision is located by kind, tick, and seed, and each run records its terminal `finalStateHash`; the gate asserts the decision sequence, the hash column, and the full terminal match state all replay to identical values. The corpus also carries one seeded (1991) `ruthless-singles-1991` run — the difficulty-aware selector routes it under the 2-ply policy while every other run stays on the default identity — so the ruthless replay contract (`finalStateHash c14n-fnv1a64-v1:7c2785c8f2aee021`) is pinned by the fixtures gate, not just the visual gate and the unit-suite golden pins.
- **Ladder separation:** a deterministic seeded underdog corpus (fast/tough wrestler vs slower small-pool challenger, 32 seeds per window — trimmed from 40 by M10-ADJ-05, player fixed at v1) shows monotonic AI win share — the strict ordering is now pinned across the **full 0–2300 span** (24 step-100 offsets, M10-ADJ-06, 0 violations verified before landing) with the wide-margin floors kept at the six historical windows (`WIDE_MARGIN_OFFSETS = [0, 250, 500, 650, 750, 1000]`), where the six-window aggregate is novice 0.027 < standard 0.139 < veteran 0.438 < ruthless 0.624 (re-measured at the trimmed size; per-window floors novice 0.034, standard<veteran 0.151, veteran<ruthless 0.063; aggregate 0.112 / 0.299 / 0.187, asserted 0.02 / 0.10 / 0.01 per-window and 0.10 / 0.20 / 0.05 aggregate). ## Performance

The `standard` path adds zero cost. Search clones skip event hashing and carry only the recent event tail, so lookahead work per decision is bounded by the ≤ 40 clone budget; the full test suite, including the ladder corpus and replay gates, completes well under the spec's 90-second acceptance target.

## Remaining external gates

Difficulty strength is a deterministic seeded behavioral assertion, not a balance claim; independent playtest balance/pacing review remains an external handoff gate (the canonical Linux portable-Chromium browser run is complete).
