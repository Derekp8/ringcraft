# M11 implementation audit — Cage and Ladder Match Variety

## Verdict

M11 adds the first match-variety milestone: steel cage and ladder matches as first-class engine configurations with deterministic replays and pinned fixtures, per `docs/superpowers/specs/2026-08-14-m11-match-variety-design.md`. Standard (variety-absent) matches serialize and hash byte-identically to pre-M11 — every existing save, fixture, replay hash, and the entire M10 corpus remains valid. The milestone is a documented product decision revisiting GDD 18.2 (which lists cage/ladder as out of scope for v1) with digital-only rules recorded in `docs/adjudication-register.md` (M11-ADJ-01/02/03), mirroring the M10-ADJ extension pattern.

## Implemented surfaces

| Area | Evidence |
|---|---|
| Variety model | `MATCH_VARIETIES = ["standard", "cage", "ladder"]` and `MatchVariety` in `src/core/types.ts`; optional `MatchConfiguration.variety` is part of the replay contract via `hashMatchState`; `createMatch` normalizes an explicit `"standard"` away so it hashes exactly like the default |
| Default identity | `variety` is `undefined` for standard matches and `canonicalSerialize` drops undefined keys at every level, so standard `hashMatchState` output is byte-identical to pre-M11; `MatchState.ladder` is optional and never assigned `null` (undefined until a ladder is set up and after retrieval/knock-down) |
| Gating (cage + ladder) | Singles-only (tag cage/ladder rejected in `createMatch` and campaign scheduling); `processCountouts` skips non-standard matches; the referee-check 31+ band never ends a non-standard match (warnings and the cumulative alert still apply) |
| Cage boundary | A `throwsOut` move converts to a cage slam — full damage, defender stays in the ring, no countout ever starts (`RingLocation` never becomes `"floor"`) |
| Ladder state | `MatchState.ladder?: { setById, setAtTick }` lifecycle: `set-up-ladder` (no dice), `climb-retrieve` (D20), `knock-ladder` (no dice, opponent's ladder only); the search clone copies the ladder object so lookahead can never mutate a live ladder |
| Escape/retrieval check | D20 ≤ AV + Charm bonus − DV + floor(opponent DAM/10) − floor(own DAM/10); roll 1 auto-succeeds; success = both feet on the floor (cage, method `"escape"`) or grabbing the object (ladder, method `"retrieval"`); failure ends the active phase with no penalty and the ladder stays up |
| Result methods | `MatchResult.method`/`MatchWpInput.method` widened with `"escape"` and `"retrieval"`; campaign `ratingResultKind` maps them to the clean-win category; WP treats them as plain wins (no DQ/countout penalty, no title bonus) |
| Validator | `enumerateTurnActions` adds `cage-escape:${charm}` (cage), and for ladder `ladder:set-up` / `ladder:climb:${charm}` / `ladder:knock` in the correct ladder states — all sharing the one legality enumeration used by every difficulty |
| AI policy | `scoreAction` scores escape/retrieval as win chance (`clampProbability(target) × 10 000`), ladder setup at 55 + beaten-down bonus (up to 95), knock-down at 45; `evaluateState` adds ±800 for ladder ownership; the `standard` path for standard matches is untouched (zero RNG, byte-identical decisions) |
| Campaign wiring | `CampaignConfig.variety` → `CampaignState.variety` → copied onto each `ScheduledMatch` at schedule time → into `MatchConfiguration` via `beginScheduledMatch`; absent = standard and hash-safe; `validateCampaignState` rejects unsupported or tag-mode varieties |

| Packaging | `fixtures/m11` added to the M9 allowlist roots; `HANDOFF-MANIFEST.json` pins refreshed (45/45 match the tree) |

## Verification

- **Full regression gate:** `npm run check` green (191 pre-M11 tests plus the 20 M11 tests) and `npm run fixtures:verify` green — M5 pinned hashes, the M10 corpus (1,050 decisions including the seeded `ruthless-singles-1991` run, pin `64e1f4af`), and both M11 fixtures all verify.
- **Default identity:** a standard match's serialization contains no `"ladder"` or `"variety"` key; an explicit `variety: "standard"` match hashes identically to the default; the M10 corpus's pinned per-decision and final-state hashes all replay unchanged.
- **Deterministic replays:** both M11 fixtures replay byte-identically through `replayFromInputLog` (AI re-derived) **and** through full headless re-derivation under the standard policy; a ruthless ladder run replays from its own input log with a stable hash.
- **Gate behavior:** scripted tests pin the cage boundary (throw-out stays in the ring, countout never fires), the countout suppression in ladder matches (a floored wrestler with a scripted countout 10 does not lose), and the DQ suppression at referee 31+ (identical setup ends in `disqualification` in a standard match and in nothing in a cage match).
- **AI coverage:** `choosePolicyAction` prefers the escape/climb win condition whenever it is legal, `evaluateState` reflects ladder ownership (±800), and the new actions appear with the full Charm range in `enumerateTurnActions`.
- **Campaign wiring:** a scheduled cage match carries `variety: "cage"` through schedule → begin → active match config, `validateCampaignState` stays clean, and a standard campaign's serialization (state and export JSON) contains no `"variety"` field.

## Playtest balance report (pacing/balance gate)

The M11 seeded playtest balance report (`fixtures/m11/playtest-balance-report-v1.json`, schema `asw91-playtest-balance-report-v1`, design in `docs/superpowers/specs/2026-08-14-m11-playtest-balance-design.md`) closes the deferred pacing/balance evidence gate with deterministic seeded analytics:

- **Corpus:** 336 matches across 11 batches — a four-rung difficulty sweep on the M10 underdog profile (extracted to `scripts/m11-playtest-batch.ts` as `makeUnderdogRecord`/`underdogSetup` and reused by the M10 test), equal-roster controls, underdog cage/ladder batches on `dominant-singles`, and a standard-tag batch; fixed 8-minute time limit; every batch pinned per-match by `winnerTeam`, `method`, `minutes`, `ticks`, and `finalHash`.
- **Win share:** by difficulty `novice 0.031 < standard 0.097 < veteran 0.207 < ruthless 0.563` (AI side), monotonic with the M10-pinned margins; by batch, including the equal-roster quirk (the quick all-rounder dominates at standard, ruthless salvages 50%) and 0% jobber wins in cage/ladder. **Re-pinned 2026-08-14** after the empirical ladder tuning (underdog endurance pools widened to `end 38`/`end 18` and `LOOKAHEAD_WEIGHT_DEPTH_2` 0.15 → 0.20) — the AI-side (weak-profile) win shares dropped because the weak challenger's pool shrank, while the monotonic ordering tightened and now holds across all 15 seed offsets 0–1500 tested.
- **Win-share confidence intervals (2026-08-15):** every win share now carries a 95% Wilson score interval (`winShareCI`, separate from the backward-compatible `winShare` point estimates) computed from the per-seed match outcomes — `novice 0.031 [0.006, 0.157]`, `standard 0.097 [0.033, 0.249]`, `veteran 0.207 [0.098, 0.384]`, `ruthless 0.563 [0.393, 0.718]` (n = 32 per underdog batch). The interval function is a pure deterministic function of the pinned outcomes, so the bounds re-derive byte-identically in the clean room. The statistical claim the ordering now carries: **ruthless's entire 95% interval lies above every lower rung's interval**, so the top-of-ladder separation is not a sampling artifact at this seed count; the middle rungs remain ordered pointwise with overlapping intervals (expected at n = 32).
- **Match length:** standard mean 4.41 min (draw rate 0.35), cage 2.69 min, ladder 2.56 min — cage/ladder are meaningfully faster (the win condition) but no longer degenerate.
- **Finish methods:** standard = pin 134 / draw 73 / submission 1; cage = escape 52 / pin 8 / draw 4; ladder = retrieval 55 / pin 8 / draw 1 — the verifier asserts the M11 method-set invariants (no countout/DQ in cage/ladder) across every row.
- **Rule finding (M11-ADJ-02 amendment):** the report's first run showed the initial escape/retrieval formula (no softening requirement, remaining-pool damage terms) produced 100% escape/retrieval at ~1 minute. The rule was amended — `ESCAPE_LEGALITY_THRESHOLD = 15` softening gate, `ESCAPE_DIFFICULTY = 5` climb penalty, damage terms corrected to the taken pool — the M11 replay fixtures were regenerated as canonical (no scripted dice) matches that exercise the softening path (Body Slam 15 → failed pin → escape/retrieval), and the report was re-pinned around the amended rule.
- **Verification:** `verify-m11-playtest.ts` (wired into `fixtures:verify`) re-derives all 336 matches and asserts every row, the aggregates (including `winShareCI`), the `reportHash` (`c14n-fnv1a64-v1:74f2eff077e3314d` since the intervals were added), four input-log replay samples, and the method-set invariants; `tests/m11-playtest.test.ts` pins the ordering on the fixture, re-derives the sweep live, validates every interval (bounds contain the share, [0,1]-clamped, deterministic, `byDifficulty` = the underdog batch's interval), asserts the ruthless-vs-lower-ladder disjoint-interval claim, checks the length/method invariants, and replays samples.

## Remaining external gates

The cage/ladder rules are a documented digital-only extension (M11-ADJ-01/02/03, human sign-off pending like every M4–M10 adjudication). The win-condition formula and gating decisions are deterministic behavioral assertions, not source transcriptions; independent review of the extension decisions remains an external handoff gate. The pacing/balance evidence gate is closed by the seeded balance report above; human playtest sign-off on its findings remains the external human gate.
